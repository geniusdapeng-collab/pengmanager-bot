# 鹏经理 AI 业务审核

一次已授权的业务动作启动审核。AI 对准确的对象快照、逐项标准和实际证据作出通过、拒绝或证据不足的判断。任何修改会生成新工作单。审核回执记录 `ai-reviewer`、工作单与快照摘要、逐项结论、模型身份、用量和供应商请求编号。历史人工记录继续按原来记录的身份读取。

媒体版权、账号归属、客户沟通许可、预算及外部平台条款需要各自的来源证据。对外动作沿用原有账号权限和用户发起的授权。是否通过业务审核由 AI 作出。实际执行和公开发布仍以供应商或站点回读为准。

## 生产审核工位

生产站点创建只读审核工作单。授权的鹏经理Codex版本机工位通过 OpenAI Responses 执行正式模型策略 `approval.decision`，有图片时将实际 PNG、JPEG 或 WebP 字节交给模型查看。审核进程使用 `OPENAI_API_KEY` 和本版 `PENGMANAGER_CODEX_MODEL`。专用 Ed25519 私钥保留在本机，站点接收限定用途的公钥。签章 API 可以领取工单、提交判断或报告失败。

在实际运行的主干版本中，先从已有本机凭据生成公钥并核实模型账户可用：

```sh
node scripts/ai-approval-worker.mjs public-key
node scripts/ai-approval-worker.mjs doctor --origin https://your-site.example
```

将第一条命令的 JSON 输出安全写入受管站点 `DATA_FILE` 同级的 `ai-approval/reviewer-public-key.json`。目录由应用使用的系统账号拥有，权限为 `0700`，文件权限为 `0600`。同一工位私有目录限单进程使用。将下面的命令加入本机受管进程的生命周期，使用同一批准过的模型账号和原生凭据加载方式：

```sh
node scripts/ai-approval-worker.mjs run --origin https://your-site.example
```

默认工位目录为 `~/Library/Application Support/PengManager/ai-approval`。使用独立工位时，将同一绝对路径作为 `--profile` 传给三个命令。关联站点是一个固定 HTTPS origin。只在隔离测试中允许本机回环 HTTP。

## 失败及恢复

- 领单返回丢失时，本机以原领取编号重领原工单。模型结果已落盘时重传同一签章回执。站点验证工作单、快照和原租约。结果落盘后站点主动移除临时工作单中的图像字节。
- 领取含图工单时，完整接收和解析响应的时限为 180 秒，响应上限为 12,001,024 字节。提交裁决或报告失败时仍为 30 秒，响应上限为 65,536 字节。领取响应超时后保留原领取编号，重试沿用原租约。站点仍按原租约起点计算 15 分钟的等待期限。
- 供应商明确拒绝或限流时，失败凭据归原租约，冷却后同一工单可重新派发。收到余额不足时，先恢复绑定模型账号的额度。执行结果未知时暂存同一租约和故障编号，供原供应商请求对账。
- 页面自动续跑同一个 JSON 请求，继续沿用原幂等键和 ETag。证据一旦改变，服务端重新验证当前快照，避免通过旧决策覆盖新内容。
- 换公钥前完成旧签名工位的在途单，保留真实审核账本并在隔离环境验证新公钥和回执。审核回执和发布回执分开核对。

当前工位可核对实际 PNG、JPEG、WebP 和完整文本。新提交的 MP4、WAV、PDF、ZIP 和 Safetensors 需要覆盖相应内容的已授权分析证据。材料不足时返回 `AI_APPROVAL_MEDIA_INSPECTION_REQUIRED` 并维持素材私有。原生视频封签记录处理、来源和导出。历史批准继续绑定原始字节摘要。

审核工位以及原生视频审核需要模型可用。生产切换前使用真实图像验证模型完成、签章读回，并确认站点原有匿名路由、登录和受保护 API。

## 嵌入 GEO 草稿

管理员使用 `POST /api/geo/engine/articles/:id/review` 审核准确草稿，提交 `contentHash` 和最多八个可选的真实样本 `sampleIds`。批准结果标为 `reviewed_for_editorial`，继续使用编辑和网站发布流程。草稿正文、摘要和样本发生变化后，旧回执会从当前视图移除。
